# v7.0.0 — Refonte « standards internationaux » (2026-10-11)

Mise en œuvre de l'ensemble des lots 0 à 3 de `docs/audit/2026-10-11-analyse-strategique-v7.md` (le lot 4, conformité et distribution, reste hors périmètre en usage personnel).

## Lot 0 — Sécurisation
- Clé API Groq saisie dans Réglages et stockée uniquement sur l'appareil ; plus aucun secret dans le build ni dans le workflow (`VITE_GROQ_API_KEY` supprimé).
- Dépendance morte `clarifai-nodejs-grpc` retirée ; `npm audit` à zéro vulnérabilité ; `.npmrc` (`legacy-peer-deps`).
- Journées calculées en heure locale (`domain/time.ts`), plus jamais en UTC.
- Identifiants uniques triables (chaînes) ; filtres et tris par date, jamais par identifiant.
- Migration v4 → v5 → v7 réellement exécutée (`data/migrations.ts`, import unique du journal localStorage vers IndexedDB).
- Insuline active, dernière injection et heure rafraîchis toutes les 60 s et au retour en avant-plan (`useNow`).
- Plafond de dose par injection (réglage, défaut 0,3 U/kg) avec dialogue de confirmation branché.
- Rappels persistés (`data/reminders.ts`, `app/notificationService.ts`) : 2e injection, phases, contrôle post-repas, recontrôle hypo, basale quotidienne ; rappels manqués affichés au retour.
- Code mort supprimé : `GlycemiaChart`, `DoseAnimation`, `PhotoMeal`, `PdfExport`, `journalStore.js`, `calculations.js`, `notifications.js`, anciens `clinicalEngine.js`, `iobCurve.js`, `dosePlan.js`, `migration.js`, template Vite.

## Lot 1 — Restauration clinique (moteur TypeScript `domain/engine`)
- Mode nuit configurable (fenêtre, seuil de correction, collation sous 1,50).
- Anti-empilement : plafond de correction à 1 U si injection < 180 min, cumul de corrections 24 h > 15 % TDD, ratio IOB / dose.
- Score de risque hypoglycémique (6 facteurs) avec réduction de dose ou blocage de la correction.
- Vitesse glycémique mesurée depuis les lectures (prioritaire sur la tendance manuelle) : chute rapide → correction supprimée, montée rapide → +20 % et injection avancée.
- Prédiction à 1 h / 2 h / 3 h avec plage d'incertitude, absorption des glucides, IOB existante et nouvelle dose.
- Codes d'alerte traduits (FR/AR) : le moteur n'émet plus de texte.
- Métriques unifiées selon le consensus international (TIR 0,70 à 1,80, TBR/TAR niveaux 1 et 2, CV, GMI indicatif).

## Lot 2 — Fondations
- Domaine et données en TypeScript strict ; `npm run typecheck` ; ESLint TypeScript.
- Schémas zod (journal, réglages, sauvegarde), dépôt Dexie sans plafond d'entrées, synchronisation différentielle.
- Sauvegarde complète (profil, journal, rappels, sans la clé API) et import validé ; import CSV capteur.
- CI sur pull request (`ci.yml`), Dependabot, couverture avec seuils, Playwright (4 scénarios).
- Accessibilité : zoom autorisé, tailles ≥ 12 px, contrastes, labels, `role="switch"`, dialogues, `aria-pressed`, thème système, polices locales, CSP au build, découpage du bundle (aliments, i18n, rapports).
- i18n : 236 clés ajoutées, dates et heures via `Intl` selon la locale, onboarding RTL.

## Lot 3 — Excellence clinique
- Onglet Rapports : indicateurs consensus, barre TIR, profil AGP (percentiles horaires), tendances, pistes ratio / ISF / basale (F8), export CSV, rapport imprimable pour le médecin.
- Profils d'insuline rapide avec DIA et pic ; IOB par profil.
- Mode Ramadan (IDF-DAR 2021) : stratification du risque, réductions suhoor et basale, seuils de rupture du jeûne, choix suhoor / iftar à la consultation.
- Parcours hypoglycémie (règle des 15) avec rappel de recontrôle et entrée de journal dédiée.
- Suivi de la basale : enregistrement rapide, rappel quotidien, statut du jour.
- Jours de maladie : contexte et vigilance renforcée.
