# v7.0.1 — Clé d'IA fournie par l'environnement, OpenRouter (2026-10-11)

## Fonctionnel
- **Fournisseurs d'IA** pour la reconnaissance photo : OpenRouter (défaut, `meta-llama/llama-4-scout`) ou Groq (`meta-llama/llama-4-scout-17b-16e-instruct`), tous deux via l'API OpenAI-compatible `chat/completions`. Le fournisseur est déduit du préfixe de la clé (`sk-or-` / `gsk_`).
- **Clé lue depuis l'environnement de build** : plus besoin de saisir la clé dans l'application. `deploy.yml` injecte `VITE_OPENROUTER_API_KEY`, `VITE_OPENROUTER_MODEL`, `VITE_GROQ_API_KEY` et `VITE_AI_PROVIDER` depuis les secrets et variables du dépôt GitHub (`OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `GROQ_API_KEY`, `AI_PROVIDER`). Aucune clé dans le dépôt.
- **Priorité** : clé saisie dans Réglages (appareil) > clé de l'environnement > aucune. Réglages affiche l'état (🔒 environnement, ✅ appareil, ⚠️ aucune) avec fournisseur et modèle, sans jamais afficher la clé de l'environnement.
- Message « clé manquante » reformulé (FR/AR) ; champ relabellisé « Clé API IA (OpenRouter ou Groq) » ; clés i18n `cleApiGroq` et `cleApiGroqDesc` supprimées (remplacées par `cleApiIa`, `cleApiIaDesc`, `cleApiEnvironnement`, `cleApiAppareil`, `cleApiAucune`).

## Technique
- Nouveau module `src/app/aiConfig.ts` : `AI_PROVIDERS`, `detectProvider`, `resolveAiConfig(userKey, env)`, `providerHeaders` (OpenRouter : `HTTP-Referer`, `X-Title`).
- `recognizeFood(file, configOrKey)` accepte une configuration résolue ou une clé brute ; lève `AI_KEY_MISSING` sans clé ; identifiants `ai_<fournisseur>_<i>_<ts>`.
- CSP au build : `connect-src` étendu à `https://openrouter.ai`. Remplacement de la balise `<meta name="version">` par expression régulière (plus de valeur codée en dur).
- `.env.example` documente les variables `VITE_*` (à copier en `.env.local`, ignoré par git).
- Dependabot regroupé (`react`, `dev-tooling`, `runtime`, `actions`), majeures TypeScript 7 / ESLint 10 ignorées ; React et React DOM 19.3.0 avec leurs typages.

## Déploiement
1. Dans le dépôt GitHub : Settings → Secrets and variables → Actions → New repository secret `OPENROUTER_API_KEY`.
2. Optionnel : variable `OPENROUTER_MODEL`, secret `GROQ_API_KEY`, variable `AI_PROVIDER`.
3. Pousser sur `main` (ou relancer `deploy.yml`) : le build embarque la clé.

**Avertissement** : une variable `VITE_*` est lisible dans le bundle publié. Usage personnel assumé : plafond de dépense chez le fournisseur, clé régénérée si elle a transité par un canal non sûr, proxy côté serveur si l'application est un jour partagée.
